# 不具合の調べ方とテスト

## まず再現条件を書く

「動かない」だけではなく、操作を番号で記録します。

```text
1. Memoを開く
2. 既存メモを編集する
3. 一文字だけ変更する
4. 保存する
5. 再度開くと変更が戻っている
```

端末、画面幅、ログイン状態、オンライン/オフラインも結果へ影響します。

## ConsoleとNetwork

Developer ToolsのConsoleではJavaScript例外、Networkでは通信を確認します。

- 400: 送った内容や形式が不正
- 401: ログイン情報がない、期限切れ
- 403: 権限やRLSで拒否
- 404: URLや対象がない
- 429: APIの利用頻度制限
- 500台: サーバー側の失敗
- pending: 通信が完了していない

AIが止まった場合、`/api/ai/generate`のStatusとResponseを確認します。

## 自動テストとは

自動テストは、入力に対して期待した結果になるかをコードで確認します。

```js
test('新規メモは復習なし', () => {
  assert.equal(resolveNewMemoReviewEnabled({}), false);
});
```

- `test(...)`: 一つの確認項目
- `assert.equal(actual, expected)`: 実際の値と期待値を比較
- 失敗時の差分: 何が期待と違ったか

## コマンド

```powershell
npm run lint
npm test
npm run build
```

- `lint`: このプロジェクトでは全JavaScriptの構文を確認
- `test`: `tests/*.test.mjs`をすべて実行
- `build`: 配信前の構文確認

このアプリはVanilla JavaScriptなので、大規模な変換ビルドはありません。それでも`build`という共通名を
用意し、Vercelや開発手順から同じ確認を呼べるようにしています。

## テストファイルを読む順番

1. テスト名を日本語の仕様として読む
2. 用意している入力データを見る
3. 呼び出す関数を見る
4. 最後のassertで期待結果を見る
5. 必要になったら実装側へF12で移動する

最初からテスト用のモックやVM設定を理解する必要はありません。

## 手動確認も必要な部分

- スマートフォンのタップと長押し
- スワイプ
- ソフトウェアキーボード表示時のレイアウト
- 画像の拡大と削除
- 別端末間のリアルタイム同期
- 音声再生

ロジックテストが通っても、これらのUI操作は実機またはブラウザの端末表示で確認します。

## 修正後に別機能が壊れる理由

同じ保存関数やCSSを複数画面が共有しているためです。変更箇所だけでなく、共有先を`Shift+F12`で確認し、
関連する自動テストと代表画面を一緒に確認します。
