# AI回答が保存されるまで

## 全体の流れ

```text
画面で質問を入力
  ↓
js/modules/* が依頼内容を組み立てる
  ↓
js/ai.js がプロンプトと依頼の種類を組み立てる
  ↓
短い処理: /api/ai/generate
長時間処理: /api/ai/jobs → api/ai/generate.js の共通生成処理
  ↓
Gemini API
  ↓
api側で最低限の形式検証・正規化
  ↓
ブラウザ側でも用途別に検証
  ↓
storage.jsで保存
  ↓
sync.jsがSupabaseへ同期
```

## ブラウザ側とサーバー側を分ける理由

- Gemini APIキーをブラウザへ公開しない
- 用途ごとのモデルと出力量をサーバーで管理する
- 不正な`action`をサーバーで拒否する
- タイムアウト、再試行、フォールバックモデルを一か所で制御する

## なぜJSON形式を使うのか

表現帳やKnowledgeは、単なる文章ではなく、タイトル、分類、例文、関連語などを別々に表示・保存します。
そのためAIには決められたJSON構造で回答させます。

AIは時々、項目を省略したり形式を崩したりします。検証は必要ですが、条件を厳しくしすぎると
内容が有用でも全体を保存できなくなります。そのため現在は、壊れたデータを防ぎつつ、
完成している意味や項目は可能な範囲で残す設計です。

## 品質と速度

- 短い分類・補助処理: fastモデル経路
- 長い解説・表現帳・Knowledge: qualityモデル経路
- 一時的な失敗: 再試行またはフォールバック
- 長文生成: Vercel FunctionとGeminiの両方に十分な待機時間を設定

## バックグラウンド生成

Knowledge、表現帳、和文英訳、英語の疑問は、呼び出し時に`backgroundContext`があれば
`js/ai-jobs.js`からジョブAPIへ送ります。すべてのAI処理が同じ経路ではありません。

`api/ai/jobs.js`は、ユーザーのJWTで認証と所有者を確認し、`knowledge_memos`表の
内部レコードとしてジョブを保持します。通常メモとはタグとブロック種別で区別するため、
この内部レコードを通常メモとして表示・整理・削除しないことが重要です。

画面を離れてもサーバー側の処理は続けられます。ただし、Vercelの実行時間、Geminiの制限、
通信障害の影響は受けます。永続キューのように無期限の実行を保証するものではありません。

ブラウザは`js/ai-job-status.js`で状態を表示し、復帰時は`js/ai-job-resume.js`が未取り込みの
結果を同じ正規化経路へ戻します。ジョブの生成成功と、利用者向けの項目として保存できたことは
別段階です。保存の検証に失敗した場合を、AI生成そのものの失敗と混同せず調べます。

## 検証の範囲

自動テストでは生成API・ジョブ・回答形式・保存や同期の統合ルールをモックで検査します。
実モデルが毎回正しく答えることや、本番のAPI利用枠が残っていることは別の確認が必要です。
